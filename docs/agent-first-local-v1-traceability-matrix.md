# Agent-First Local v1 Traceability Matrix

Last updated: 2026-07-08

## Purpose

Map the active v1 local/agent-first goal into concrete requirements, current
evidence, gaps, and restrictions.

This document is the completion-audit entry point. It prevents the architecture
work from looking complete just because the principles have been written down.

Companion evidence inventories:

- `agent-first-local-v1-code-audit.md`
- `agent-first-local-v1-cli-cas-audit.md`
- `agent-first-local-v1-api-surface-inventory.md`
- `agent-first-local-v1-remote-compatibility-boundary.md`

Recent storage evidence: `project status.storage.contentModel` makes text and
timeline live state, agent projection files, host revision registries, and
non-media immutable revision blobs explicit; each entry now carries a
`contentRegistry` object that names the SQLite non-media revision registry and
marks `mediaAssetTable: false`; `clash doctor storage` validates that this
model does not point text/timeline content at media asset storage or
agent-writable canonical state. `storage.localSecrets` exposes machine-local
secret paths as protected local-only state. The latest storage doctor repair
black-box E2E verifies both contracts through the public CLI.

Recent room/trace evidence: local-api room sync tests now seed private
`chat_message` runtime events containing tool-log/local-path data for the same
project and verify that the explicit room mirror exports only `room_message`
rows; the shared `selectRoomMessagesForMirror` selector has focused unit
coverage that ignores session trace inputs, keeping raw agent traces out of the
room sync payload.

Recent trace retention evidence: `project status.collaboration.tracePolicy`
now publishes raw-agent-trace sync admission plus retention contracts. Raw
traces remain `local-only`, sync admission is denied by default until explicit
user opt-in or team policy exists, and retention lasts until per-session
deletion through `DELETE /api/v1/sessions` or `clash sessions delete`, which
clears `runtime_session` and `chat_message` rows.

## Status Legend

- `Aligned in code`: current implementation already satisfies the requirement.
- `Partially aligned`: current implementation points in the right direction but
  has known gaps.
- `Spec only`: architecture is documented but implementation remains.
- `Conflict`: current implementation contradicts the v1 target.
- `Remote only`: the capability exists in cloud/remote path but not local.
