## Design Context

### Users
Clash is a collaborative creative-video workspace for editors, producers, and AI agents working on the same project graph. Users move frequently between canvases, timelines, project media, and chat, and need to attach the right working context without memorizing internal IDs or leaving the composer.

### Brand Personality
Focused, tactile, and quietly confident. The product should feel like a refined creative tool: approachable enough for direct manipulation, precise enough for production work, and transparent about what the agent can see and act on.

### Aesthetic Direction
Use Clash's warm off-white surfaces, stone and slate typography, coral action accent, restrained borders, and soft elevation. Favor editorial command palettes and compact studio controls over generic dashboard cards. Support both light and dark themes through existing semantic tokens. Preserve generous breathing room in discovery surfaces while keeping routine canvas controls dense.

### Design Principles
1. Make scope visible: label whether an item comes from the current canvas, another canvas, project assets, or a timeline.
2. Put the user's present working context first; broader project content is discoverable but lower priority.
3. Prefer one searchable, keyboard-operable surface over several modality-specific menus.
4. Use real project/runtime state and stable identities; never imply that an agent can access context that is not actually sent.
5. Keep creative work in view: overlays should feel anchored to the composer, avoid covering the entire canvas, and remain responsive at narrow widths.
